================================================================================
  PLAN COMPLETO 6 SEMANAS - SAAS DE INVENTARIOS
  Django + React + TanStack Router/Query + Bun + Cloudinary
================================================================================

STACK TECNOLÓGICO FINAL:
------------------------
Backend:    Django + DRF + PostgreSQL + JWT + Cloudinary
Frontend:   React + TypeScript + Bun + Vite
Router:     TanStack Router (file-based routing)
Data:       TanStack Query (server state)
Forms:      TanStack Form (validaciones tipadas)
UI:         shadcn/ui + Tailwind CSS
Storage:    Cloudinary (imágenes)
Deploy:     Railway (backend) + Vercel (frontend)

EN ENTREVISTAS - PREGUNTAS COMUNES:
------------------------------------

P: "Cuéntame sobre tu proyecto más reciente"
R: "Construí un SaaS completo de inventarios con una característica única:
   plantillas dinámicas. La idea es que diferentes negocios necesitan diferentes
   campos. Una ferretería necesita 'medida del tornillo', pero una tienda de
   ropa necesita 'talla' y 'color'. Implementé un sistema donde el usuario
   selecciona su tipo de negocio y el formulario se adapta automáticamente.

   El desafío técnico fue validar estos campos dinámicos tanto en backend
   (Django con JSONField) como en frontend (TanStack Form con Zod dinámico).

   El resultado es que con el mismo código puedo servir a ferreterías,
   tiendas de ropa, farmacias, todos con sus necesidades específicas."

P: "¿Por qué elegiste TanStack sobre otras librerías?"
R: "TanStack Router me atrajo por file-based routing similar a Next.js pero
   con más control. Y TanStack Query porque elimina muchísimo boilerplate
   comparado con Redux: manejo automático de loading/error states, caching,
   refetching, optimistic updates... todo out-of-the-box.

   Además está en auge y quería experimentar con herramientas modernas.
   El resultado fue menos código y mejor developer experience."

P: "¿Cuál fue el mayor desafío técnico?"
R: "Sincronizar las validaciones entre backend y frontend para los campos
   dinámicos. Si el usuario agrega un campo 'talla' requerido, el backend
   debe validarlo, pero el frontend también debe mostrar error antes de enviar.

   Lo resolví con un esquema JSON común que ambos leen: el backend valida
   contra custom_fields del template, y el frontend genera un schema de Zod
   dinámicamente en runtime basado en el mismo JSON.

   También optimizar queries fue clave: con select_related y prefetch_related
   bajé de 20+ queries a 3 queries por request en algunos endpoints."

P: "¿Cómo manejaste el deploy?"
R: "Usé Railway para backend porque su integración con PostgreSQL es excelente
   y Vercel para frontend por su velocidad. Configuré CI/CD con GitHub Actions:
   los tests corren automáticamente y solo se deploya si pasan.

   Para imágenes usé Cloudinary en lugar de guardar en BD o filesystem porque
   incluye CDN, optimización automática y transformaciones on-the-fly. Además
   su plan free es generoso para un portfolio."

P: "¿Qué harías diferente si lo hicieras de nuevo?"
R: "Empezaría con tests desde el día 1, no al final de la semana. También
   consideraría Next.js para el frontend porque el SSR puede mejorar el SEO
   si eventualmente quiero que sea público.

   Y añadiría feature flags desde el inicio para poder activar/desactivar
   funcionalidades sin redeployar."

P: "¿Cuáles son los próximos pasos para este proyecto?"
R: "Tres cosas: primero, integrar Stripe para que sea un SaaS real con pagos.
   Segundo, una app móvil con React Native que incluya escáner de códigos de
   barras. Y tercero, OCR para crear productos automáticamente desde fotos
   de facturas usando Tesseract o la API de Google Vision."


STORYTELLING PARA LINKEDIN/NETWORKING:

"Construí este SaaS porque noté que las soluciones de inventario son o muy
genéricas (sirven para todo pero no son ideales para nada) o muy específicas
(perfectas para un negocio pero imposibles de adaptar).

Mi solución es un término medio: plantillas personalizables. Empiezas con
una plantilla para tu industria, pero puedes ajustarla a tu negocio específico.

Lo interesante fue implementar formularios que cambian dinámicamente. Usé

la estructura que viene del backend.

El resultado: un sistema flexible que puede crecer con el negocio del usuario."
